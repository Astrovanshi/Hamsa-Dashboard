# Synthetic ingestion vertical slice

`SyntheticIngestionPipeline` is a local, network-free example of the ingestion boundary. It is not an exchange provider and accepts only caller-supplied files and metadata.

## File-to-observation path

1. A `SyntheticFileSpec` supplies dataset/parser identity, source identifier, source/document/publication dates, publication timestamp, and optional EOD session date. Production ingestion timestamps are generated by the system in UTC. There is no caller-supplied ingestion timestamp. Deterministic clock injection and explicit replay timestamps require `replay_mode=True`; these are stored separately as `replay_timestamp`. Point-in-time `hamsa_known_as_of` uses actual ingestion timestamps only.
2. Original bytes are archived by SHA-256 through `archive_approved_source`; the archive refuses unapproved retention. The raw-file row records its content checksum and archive path.
3. A source-document revision and source sighting are recorded before parsing. Exact bytes for the same provider/dataset/source identifier do not create a source revision. The same parser plus successful extraction is idempotent. Re-parsing identical bytes with a newer parser appends a parser/extraction processing revision, preserving prior observations and their lineage. Changed bytes append a numbered source-document revision linked to its predecessor.
4. Dataset-specific CSV parsers retain line-based extraction locations. Required columns, dates, numeric values, explicit units, instrument identity, and row-level quality are validated.
5. Security-master records map by validated ISIN. Separate NSE and BSE instrument/listing IDs point to one canonical security. Issuer and security IDs come from an explicit reviewed identity map, so a changed ISIN can retain the assigned canonical IDs without name-based or automatic identity inference. Missing mappings and conflicting instrument/date mappings are quarantined with a source locator.
6. Normalized observation batches, quarantine rows, and a successful parser-processing record commit inside a DuckDB transaction. A write failure rolls back the entire file's normalized rows and started parser attempt; the failed attempt is then recorded separately. The archive sidecar manifest is written atomically before database persistence. `recover_archived_sources()` finds archived source/parser pairs without a successful committed run and retries from the checksum-addressed archived bytes, allowing a crash after archival to recover without duplicate observations.

Financial values are accepted only when their stated unit matches the explicitly configured metric unit. Unknown units are quarantined; no conversion or zero-filling is inferred. Blank values remain SQL `NULL` with `quality_status='missing'`. Conflicting source facts remain stored and surface as conflicted in the point-in-time snapshot. Restatements append a new revision and supersession link. EOD corrections preserve the previous raw price row and link a new observation to it. Corporate action filings retain their terms and effective dates; incomplete terms do not produce adjustment factors.

The synthetic fixtures in `tests/fixtures/synthetic/` contain NSE/BSE security masters, valid and ambiguous mappings, venue-specific EOD prices, a deliberately invalid price, quarterly results with missing and invalid-unit values, a later-published restatement, an independent conflicting filing, corporate filings, and a malformed file. The fixtures use synthetic ISINs and issuer labels.

`IngestionReport` uses mutually exclusive row/file outcome counters. `accepted` counts new independent normalized records; `revised` counts records that supersede an earlier value or extraction; `rejected` counts invalid rows or one malformed file; `quarantined` counts unresolved rows; `duplicates` counts repeated source records skipped after a successful same-parser extraction. A revised record is never also accepted. A successfully repeated file reports its parsed row count as duplicates (or one duplicate for a valid empty file). Per-file checksums and errors remain visible. The integration tests replay identical bytes into a fresh DuckDB database and compare normalized observations, revision lineage, and provenance; actual ingestion times may differ between replays and remain distinct from deterministic replay timestamps.

Run with the repository's pinned DuckDB environment:

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The pipeline does not call NSE/BSE, download data, activate providers, implement screening engines, or build the dashboard.
